# Changelog

## Unreleased

### Added
- `engine::paid` (task T1 part B, D6/D13): the type-enforced paid-call gate.
  - Doctests prove that (1) `PaidProvider` and `BudgetLedger` cannot be implemented outside the crate (both are sealed traits) and (2) `Attempt` cannot be constructed outside the crate; every provider request carries a ledger-issued `Reservation`.
  - `PaidGate::call` commits the reservation to SQLite before dispatch (blocking ledger work runs on `spawn_blocking`); at the cap it returns `SkippedBudget` and on any other ledger failure `LedgerUnavailable` — both with zero provider requests. The gate defensively verifies the issued ticket matches the request (provider and bound) and fails closed on a mismatch without dispatching. No automatic retries: each retry is a new `call`, i.e. a new reservation.
  - Settlement lifecycle: `Ledger::settle`/`settle_by_id` now return a `SettleReceipt` reporting the authoritative recorded charge (the first charge wins on an idempotent replay); a racing or replayed settlement is disclosed as `Settlement::AlreadySettled { recorded_micros, reported_micros }`. Reported charges settle idempotently (ticket consumed); unknown charges, ambiguous timeouts and cancellation keep the open liability at its estimate; a failed settlement write still returns the body with `Settlement::Deferred`, which carries `reported_micros` so a reported charge is never discarded. `PaidCallRecord` (provider, reservation id, actual/estimated cost, settlement state) is the disclosure metadata the evidence package will carry.
  - `PaidCallRecord::over_bound_micros` discloses provider-bound violations: `Some(actual - max_cost)` whenever a reported actual exceeds the reserved bound (the provider's code-set bound is wrong). Above-bound actuals are recorded as-is, never clamped; if settlement fails, the books undercount by `over_bound_micros` until reconciled.
  - `Clock`/`SystemClock`, `OPERATING_BUDGET`/`EVAL_BUDGET`; eval and operating gates share the gate code but not their budgets (isolation is test-verified).
  - `BudgetLedger` is sealed for fail-closed testing: only in-crate implementations exist (they are reviewed), tickets cannot be minted outside `store::ledger`, so fakes can only fail, park or delegate to a real `Ledger`.
  - Ledger read API for auditing: `Ledger::reservations` (all rows, all states), `ReservationState::Settled`, `ReservationInfo::actual_micros`.
  - tokio added to workspace dependencies (rt/time/sync; engine dev-deps add macros and rt-multi-thread).
  - 26 offline unit tests with mocked providers on tempfile ledgers + 2 new ledger integration tests. New lifecycle coverage: durable-before-dispatch (an independent ledger connection checks the reservation row is committed and open before the provider proceeds), cancellation during reservation and during settlement (the detached settlement still lands), the join-error branches (a panicking reserve fails closed; a panicking settle defers with the reported charge), a provider panic (row stays open, counted at estimate), ticket-mismatch fail-closed, bound-violation disclosure, and a racing reconciliation and an equal-amount replay (both `AlreadySettled`). Known gaps: no real provider clients yet (the Exa/Parallel reference clients come with the eval baseline, T5/T10; the OpenRouter judge with T6; capped paid fallback in M3); best-effort upstream cancellation is deferred to those real clients; nothing yet runs `expire_open_older_than` on a schedule or reconciles late charges (daemon work, T2); the reserve-time storage failure is now tested through a fake ledger (the part A file-permission gap stays as recorded below); abrupt-process-kill durability is not tested (it relies on SQLite WAL); the user-facing decision request for a bound violation (D19) is not built yet.
- `docs/ROADMAP.md`: maps milestones M0 to M4 to the M1 build steps and review tasks T1 to T11, with status and the decisions still waiting on the user.
- Cargo workspace (D2): `engine` library, `wsm-mcp` and `wsm-eval` binaries (placeholders), and `rust-toolchain.toml`. Builds and tests in WSL2.
- `engine::store::ledger` (task T1 part A, D6/D13): a SQLite budget ledger in integer micro-USD.
  - A reservation is committed in one `BEGIN IMMEDIATE` transaction before its ticket is returned, so concurrent reservations cannot exceed the cap.
  - Liabilities survive restart; settlement is idempotent; expiry charges the estimate.
  - In-memory and non-WAL storage is refused. Concurrent first opens migrate safely.
  - The `Reservation` ticket cannot be built or cloned outside the ledger (compile-fail doc-tests).
  - 14 offline integration tests. Known gap: a storage failure on `reserve` after a successful `open` cannot be provoked through file permissions, so that path is verified by code inspection only.
- Project folder with Git, README and CHANGELOG. The README links to the authoritative Vision.md (SEARCH-01 to SEARCH-09). No code yet.

It records the route (Rust-native, eval-first), the agreed targets, the contracts for result semantics, cache freshness, untrusted content, source access, cost and comparison, and the M1 validation matrix. An independent review ran 2 rounds; the final fixes are not yet re-verified by the reviewer.

### Changed
- Decision D19 (user, 2026-10-12): when a provider charges more than the reserved maximum, the engine discloses it (`over_bound_micros`) and asks the user for a decision. It never disables the provider automatically. Recorded in the design doc and TODOS.md.
- Engineering plan review of the design (2026-10-11). It confirmed the R2-1 to R2-5 office-hours fixes, and you approved D2 to D18. These add: a 3-crate workspace; one engine daemon that owns the budget, cache and ledger, reached by Pi over loopback HTTP with an Origin check, a bearer token and TLS when exposed; durable, type-enforced paid-call reservations; `degraded` and `no_match` status rules with required/optional stages; classification through the swappable Judge slot; quota tracking and origin-scoped free API keys; a byte-capped cache with separate discovery and content TTLs; a sealed acceptance set with a locked analysis plan; a paired grader-agreement gate; comparative cost per system; and a judge influence boundary. An outside reviewer model contributed 8 of these findings. The review record and implementation tasks T1 to T11 are at the end of the design doc.
